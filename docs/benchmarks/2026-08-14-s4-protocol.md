# S4 protocol orchestration checkpoint

Date: 2026-08-14

Command: `make sim-s4-protocol`

## Scope

This architecture-neutral checkpoint runs the nominal S4 mission without
physics. It creates independent coordinator, mobile-base, robot-arm, and zone
authority identities; enrolls mutual trust; grants capability-scoped authority
leases; starts one real `umpd` per machine; and drives deterministic local
controller fixtures through the bounded adapter sockets.

The mission writes both a 22-record JSONL event trace and a JSON invariant
report. The verifier fails the run unless all six tasks complete exactly once,
the exclusive zone is released after commit, handoff revisions are ordered,
source and destination evidence carry their authenticated machine identities,
and ownership changes from arm to mobile only at commit.

The coordinator communicates only through authenticated QUIC using
`ump issue-task` and `ump query-task`. It executes arm pickup, mobile approach,
arm placement, arm release, mobile payload receipt, and mobile delivery. Each
task is accepted, started, receives progress, reaches succeeded, and is read
back through protocol reconciliation.

## Result

- Six task acknowledgements were accepted.
- Six terminal reconciliations reported succeeded.
- Both executor journals advanced independently to sequence 13.
- The arm acquired and released the exclusive transfer-zone reservation.
- Handoff revisions progressed monotonically from proposed through committed.
- Two independently authenticated evidence records changed authoritative
  ownership from the arm to the mobile base exactly once.
- The emitted JSONL trace contained the expected 22 task and coordination records.
- No executor journal, ROS topic, or controller-specific API was read by the
  coordinator.

The checkpoint found a short-lived QUIC connection lifecycle issue during its
first run. `issue-task` and `query-task` now explicitly close completed
connections and use bounded retry while an executor returns to its accept loop.
The complete mission passed after that fix.

Two fault slices also pass:

- Cancellation during active execution propagates through authenticated UMP,
  becomes locally visible as `cancel_pending`, stops the controller fixture,
  and reconciles as `cancelled`.
- Executor restart preserves accepted work for later execution. Restart during
  running work recovers it as `unknown` with `inspection_required=true`, rather
  than inferring a physical outcome.
- Lease expiry during active execution is detected by the daemon maintenance
  tick, stops the controller fixture, and reconciles as inspection-required
  `unknown` without a fabricated result.
- Authenticated task issuance, execution, and reconciliation succeed through
  deterministic UDP relay profiles covering 5% and 10% packet loss, burst
  loss, 50-500 ms delay, and deterministic +/-100 ms jitter.
- Emergency safety state prevents an accepted task from being claimed. A newer
  normal-state revision permits the same durable task to execute.
- Reservation expiry during transfer moves the handoff to inspection-required
  `unknown` while preserving the arm as authoritative owner.

## Boundary

This proves runtime orchestration and the UMP-to-adapter contract. It does not
claim physics, navigation accuracy, arm reachability, payload stability, or the
S4 fault campaign; those remain part of the native Gazebo checkpoint.

The native checkpoint now also asserts explicit `rejected:grasp_failed` and
`dropped` payload-plugin states. The controller-side blocked-path watchdog is
covered by deterministic ROS unit tests; native obstacle execution remains an
unverified CI gate until the Gazebo job runs on Ubuntu.

The full native campaign is now configured to drive failed grasp through a UMP
task and require its stable ROS error in the durable timeline. It also starts a
transfer, forces a physical drop, and requires the payload monitor and local
coordination authority to converge to inspection-required unknown while arm
ownership remains authoritative. The authority transition has deterministic
Rust coverage; live Gazebo evidence remains pending native CI.

Protective stop is configured to cancel a running navigation action, emergency
stop then escalates the persisted safety state, and a subsequent normal event
must neither reset the latch nor permit accepted work to be claimed. The latch
precedence is covered by the ROS package tests; live evidence remains pending.

Transform fault mapping is covered by deterministic tests for stale and future
timestamps, malformed quaternions, translation and rotation discontinuities,
and valid static/small updates. Live TF fault injection remains part of the
native embodied checkpoint.

Spatial samples now populate position and orientation uncertainty from either
fixed adapter declarations or a timestamped ROS localization-quality message.
The package gate rejects missing, stale, malformed, and over-limit uncertainty.
The native campaign injects a 2.0 m estimate, requires
`localization.position_uncertainty`, and then requires recovery to 0.02 m; this
remains configured rather than observed evidence until native Gazebo CI passes.

The protocol fault campaign also drives a zone-authority revocation through its
local sensor boundary during transfer and verifies inspection-required unknown
with arm ownership preserved. A protocol 1.1 coordinator negotiates minor 0
with a compatibility-capped 1.0 arm and completes one authenticated task. This
uses the same reference binary in compatibility mode, not an independent legacy
implementation.

Native CI now has a separate embodied-fault command. It drives the exact ROS
action payload used by the nominal mission, injects stale and discontinuous
odometry TF plus excessive localization uncertainty, and
creates a validated static wall across the mobile route. Passing evidence must
include `tf.stale`, `tf.translation_discontinuity`,
`localization.position_uncertainty`, a failed task, and
`ros.navigation_blocked`; this gate is
configured but has not been observed on the local emulated Gazebo environment.

That native command also creates `zone_intruder.sdf` inside the physical
transfer bounds. The Gazebo monitor and ROS zone adapter must cause local
resource revocation, inspection-required unknown handoff state, and preserved
arm ownership before the TF and obstacle slices continue.

The model-swap gate uses the same world URI, UMP identities, coordinator,
capabilities, task payloads, and six-step mission with a compact mobile base
selected only through `UMP_MOBILE_MODEL_VARIANT=alternate`. Static conformance
checks prove both resources expose the same root link and ROS/Gazebo endpoints
while their physical signatures differ. A second native trace and invariant
report are configured under `artifacts/s4-model-swap`; successful live evidence
is still pending native CI.

The architecture-neutral S4 run now also emits four read-only inspector
snapshots. Its verifier passed expected identities, six successful tasks,
released reservation, committed ownership, structured event histories, and
absence of secret credential fields. Native nominal, model-swap, and embodied
fault targets export the same bundle, with the fault target evaluated against
expected failed-task, unknown-handoff, and latched-emergency outcomes.

The native nominal and model-swap targets also configure a Linux `/proc`
sampler for the mobile, arm, and zone daemons. Unit fixtures validate passing
and failing report gates, and a Linux container smoke validates live sampling.
No native Gazebo resource values are reported here; the measurement method and
acceptance criteria are defined in `S4_NATIVE_PROFILE.md`.
